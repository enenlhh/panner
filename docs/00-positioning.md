# 00 Panner 的定位与边界

> 本篇定义 Panner 要解决的问题、产品形态及其与宿主 agent 的分工；各步骤的输入、规则和产物由后续文档细化。

## 一句话定位

Panner 是通过 MCP 接入宿主 agent 的**系统综述题名与摘要筛选工具**。它接收检索记录和经综述团队确认的纳入排除标准，在预先规定的排除条件下，以尽量低的总成本，自动排除尽量多有充分排除依据的 citations，并将其余记录送往后续评估。

这里的“尽量多”以保护可能符合标准的研究为约束。未能形成足够排除依据的记录继续流转；“保留”表示尚需后续评估，不等于最终纳入综述。Panner 的工作范围从检索导出的记录开始，到题名与摘要阶段的排除、后续评估交接和过程报告为止。

## 为什么这样设计

检索池中的大部分记录最终不会纳入综述，但两种错误的后果不对称：多保留一条会增加后续工作，错误排除一条可能使相关研究不再被评估。因此 Panner 先固定**什么证据允许排除**，再提高自动排除数量并降低成本；不能为多排除几条记录而放宽证据要求。

“高确定性”在此指**自动排除有可检查的依据，且达到预先规定、经过验证的生效条件**。它不是模型自称有把握，也不保证单条判断必然正确。安全性需要在适当的标注数据上检验；达不到预设要求时，记录应继续评估，不能用节省的费用抵消漏排。

“低成本”按完整工作流衡量，包括标准编译、批量判断、后续模型调用和人工复核。便宜的规则和受约束判断先处理适合它们的记录，更费时的判断集中在仍未解决的部分。成本、自动排除量和剩余人工工作量应一起报告。

## 工作原则

1. **先记录标准，再编译执行。** 01 帮助综述团队形成并确认当前资格标准文本；03 在编译原子信号与组合规则时，就具体缺口继续问用户，必要时更新标准版本。开放问题由团队决定，可执行协议另行确认后用于批量筛选。
2. **回答与排除分开。** 规则或模型回答记录中的具体问题；Panner 按冻结协议和固定的生效条件计算记录结论。信息未报告或答案不稳时，继续评估。
3. **按依据分配工作。** 结构化事实由确定性规则处理，需理解题名摘要的问题交给受约束的判断后端；仍未解决的记录再进入更深入的模型评估或人工复核。后端可替换，但不能改变协议赋予答案的含义。
4. **每次排除都可回查。** 保留原始记录、标准原文、协议版本、每道问题的回答、模型和阈值信息以及人工决定。记录层结论由这些材料和固定规则推导，可解释何种依据使排除生效。
5. **agent 负责理解，工具负责批量处理与核对。** agent 判断来源 citation 文件的实际结构、提出字段对应并组织转换；批量文件处理、判题、计数和报告借助工具执行并落盘，不把成千上万条 citations 逐条送进对话上下文。

## agent、工具与用户的分工

| 参与者 | 负责什么 |
|---|---|
| 综述团队 | 提供和确认目标与标准；裁决会改变筛选含义的歧义；复核未决记录；接受最终报告 |
| 宿主 agent | 与用户记录初始资格标准，并在编译时澄清具体规则；理解不同来源的 citation 结构并建立统一 citation 池，解释计划和结果，收集确认与裁决，调用 Panner 的 MCP 工具 |
| Panner MCP server | 提供固定数据结构与校验、批量处理能力、协议校验与冻结、判定规则、溯源、复核材料与报告 |
| 判断后端 | 按所在阶段的接口回答原子问题或作受约束的复判，并返回该阶段要求的回答与依据；不自行改写标准或决定最终排除规则 |

宿主 agent 提供交互能力，Panner MCP server 提供受约束的计算与记录能力。正确性条件必须由工具检查，不能只写在某个 agent 的提示词里。用户可以随时询问一条排除的来由，agent 从保存的材料中解释；修改标准或判定规则时形成新版本并重算受影响的结果。

## 产品形态

Panner 的首版发行形态是**本地 MCP server**，供宿主 agent 连接并调用。使用者安装 Panner，在自己的宿主中注册 Panner 的启动方式，并为每项综述指定宿主与 Panner 都能访问的 workspace。之后，使用者在宿主对话中提出筛选任务；宿主发现并调用 Panner 提供的工具。不同宿主使用同一套工具、数据契约和判定规则，只需分别配置 MCP 连接。[MCP Python SDK 的宿主接入示例](https://py.sdk.modelcontextprotocol.io/get-started/real-host/)展示了这种本地接入方式。

## 工作流编排

一次筛选按四个环节顺序进行，每个环节只读取前一环节已确认的产物。workspace marker 记录活动标准、citation、去重池、协议和筛选结果（`active_eligibility_criteria`、`active_citation`、`active_pool`、`active_protocol`、`active_screening`），这张状态表就是编排的依据：

| workspace 状态 | 当前环节 | 动作 | 宿主入口 |
|---|---|---|---|
| 无确认标准 | 01 | 与用户确立并确认资格标准 | prompt `establish_eligibility_criteria` / `panner_eligibility_guide` |
| 有标准、citation 或去重池尚未确认 | 02 | 建立 `citation.jsonl` 并运行固定去重 | prompt `build_citation_pool` / `panner_citation_guide` |
| 有池、无冻结协议 | 03 | 把标准编译为协议并冻结 | prompt `compile_screening_protocol` / `panner_compile_guide` |
| 有冻结协议 | 04 | 基于原子信号问题的筛选 | `panner_screen_guide` |

宿主的统一入口是 prompt `start_or_resume_screening` 或工具 `panner_workflow_status`：先查询 workspace 当前处于哪个环节、各环节已产出什么、下一步该做什么，再按当前环节的指引执行。环节完成的判定与版本一致性由工具校验；版本被改动或 manifest 不一致时，状态报告为可修复的完整性错误，而不是继续向前。

**宿主的知识来源**：宿主 agent 在运行时读不到本目录的文档，它的全部规则与知识必须由 MCP 连接本身携带。PANNER 的 server 在初始化时返回 instructions（PANNER 是什么、先调 `panner_workflow_status`、流程概览）；工具与 prompt 之外，server 另暴露六份宿主可读资源（`panner://workflow` 编排与环节产物、`panner://contracts/criteria`、`panner://contracts/citations`、`panner://contracts/protocol` 三份数据契约、`panner://examples/citation` 与 `panner://examples/protocol-draft` 两个示例）。资源是英文运行时正本；本目录的中文文档供人审阅，两者的内容必须对应——文档中的细节都要能在资源中找到，资源的内容也要能在文档中找到出处。

发行包按四个层次组织，[01](01-eligibility-criteria.md)–[04](04-screening.md) 每篇内部也按同一骨架分节：**职责与判断逻辑**（本环节做什么、规则是什么）、**数据契约**（输入与产物的固定结构）、**MCP 工具与调用契约**（接口与两段式调用）、**宿主工作流指令**（运行时正本随 server 分发，文档保存中文对照）：

1. **工作流编排：**总入口与状态机——从 workspace 状态判定当前环节、下一步动作与所需工具；环节顺序与完成条件由工具校验。
2. **环节指令：**每环节给宿主 agent 的运行时规则。凡宿主必须遵守而工具无法机械校验的规则必须进入指令；指令英文正本随 server 分发，docs 保存逐句中文对照。
3. **数据契约：**规定 `eligibility-criteria.md`、不可变的 `citation.jsonl`、派生的 `citation-pool.jsonl`、`protocol/vN/protocol.json` 及后续判定记录的含义和关系，使不同宿主处理的是同一项筛选工作。
4. **MCP 工具与 workspace：**以明确的输入输出结构处理大量数据、检查产物、执行固定判定规则并生成报告；每项综述的 workspace 独立保存原始来源、确认版本、协议与判断记录。[MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)定义工具的发现、调用与输入结构。

能够连接本地 MCP server、与其共享 workspace 文件并与用户对话的宿主 agent 可以运行 Panner。宿主 agent 负责理解用户意图与不固定的输入结构；Panner 负责校验数据与步骤状态，并按固定规则处理和记录结果。

## 怎样判断它是否达到目标

- **安全性：**在有适当真值的评估中，报告自动排除造成的漏排，并逐条保留排除依据；最终纳入研究名单与题名摘要阶段标签要分别解释，不能混作同一种真值。
- **工作量：**报告自动排除多少、进入更深入模型评估多少、交人工多少；保留记录进入后续评估的含义清楚。
- **成本：**报告各阶段调用与人工处理成本，说明减少工作量的代价。
- **可核查性：**从一条结论能回到原始记录、原标准、冻结协议、原子回答和使其生效的规则；存储的回答与版本足以重算结论。
